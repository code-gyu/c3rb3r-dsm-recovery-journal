## 14 攻击入口调查与系统恢复边界

### 外部参考事件的漏洞判断不能直接移用

参考仓库作者最初猜测 GitLab RCE，后来依据其 DSM 登录日志与 RAM 中的登录插件环境注入残留，将入口高可信指向与 CVE-2024-10441 一致的技术链。其资料仍注明完整 HTTP 请求和执行链存在缺口。[S09]

本案目前没有同等完整的入口取证证据。不能把参考作者的日志时间、cron 文件、攻击链和 GitLab 恢复数量写成本案经历；也不能因样本相同直接认定从相同漏洞进入。

[Synology-SA-24:20 公告](https://www.synology.com/en-global/security/advisory/Synology_SA_24_20)列出 CVE-2024-10441 等相关漏洞及修复版本。其中 DSM 7.2.1 分支的门槛为 7.2.1-69057 Update 6；如果本案实际为该分支 Update 4，属于值得调查的未修补线索。该门槛只针对该公告，不代表 2026 年全部安全更新要求。[S10]

### 仍需调查的来源

保留并分析认证、DSM Web、nginx、系统日志、任务调度数据库、cron、服务及启动项，核对账号和管理员组、SSH 公钥、套件修改、容器配置、异常下载与出站记录。NAS、路由器和其他设备的日志应分别建立时间线，标明时钟偏差及重置造成的证据缺失。

扫描请求、登录失败、计划任务残留和日志中的删除命令各有证据范围。删除命令被记录不单独证明目标原先存在或删除成功；没有访问到完整请求也不能编造利用载荷。排查摄像头或路由器时需要它们自身的证据，不能仅按掉线时间归因。

### 可信系统恢复仍是后续工作

恢复数据与恢复系统信任是两个分别验收的任务。本文截点没有完成持久化清除、凭据审计或可信重建。建议在关键数据与证据妥善保全后，从可信介质和软件包建立受支持的系统环境，补齐更新，重新创建配置，再导入经验证的业务数据。

在干净设备上更换可能暴露的 NAS、SSH、同步、云服务和应用凭据，撤销旧会话及令牌，并重新核查外网映射、VPN 或访问网关。旧镜像层、脚本、插件和系统目录不能未经检查就覆盖回新环境。备份卷不要作为可写共享长期挂在受灾系统上。

重连生产网络前，分别验证数据可用、应用一致性、管理员与持久化配置、必要网络暴露和独立备份恢复能力。这里描述的是后续计划，没有把 NAS 当前状态标记为已清除感染。
